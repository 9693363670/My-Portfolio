## 05 — My Analytics Workflow

<p align="center">
  <b>BUSINESS QUESTION</b> → <b>DATA PREPARATION</b> → <b>ANALYSIS</b> → <b>VALIDATION</b> → <b>VISUALIZATION</b> → <b>INSIGHT</b>
</p>

| Stage | Focus |
|---|---|
| Understand | Define the problem and the decision that needs support. |
| Prepare | Inspect data quality, missing values, duplicates, and inconsistencies. |
| Analyze | Use SQL, Python, or Excel to investigate patterns. |
| Validate | Check calculations, definitions, and conclusions against the data. |
| Communicate | Present findings through clear visuals and concise explanations. |
| Recommend | Explain implications, limitations, and possible next steps. |

I aim to make every project explain not only **what was built**, but also **which question it answers, how it works, and what its findings mean**.

## 06 — Beyond the Dashboard

I believe a strong analytics project should be understandable and reproducible.

Where appropriate, my project documentation includes:

- **Problem statement:** The question being investigated.
- **Data source:** Dataset origin, scope, and limitations.
- **Methodology:** Preparation steps, transformations, and analytical logic.
- **Metric definitions:** How KPIs are calculated.
- **Findings:** Observations supported by the available evidence.
- **Limitations:** What the analysis cannot establish.
- **Next steps:** Further analysis or improvements worth exploring.

This structure helps make analytical work easier for recruiters, collaborators, and business stakeholders to evaluate.
